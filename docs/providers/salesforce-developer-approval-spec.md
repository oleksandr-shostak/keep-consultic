# Keep ↔ Salesforce Cases Integration Spec (For Developer Approval)

Version: 1.0  
Date: 2026-02-18  
Owner: Keep team (Consultic)

## 1. Purpose

This document defines the integration contract between Keep incidents and Salesforce Cases for implementation and approval by a Salesforce developer.

Integration goals:

1. Keep incident lifecycle creates/updates Salesforce Case.
2. Salesforce Case lifecycle updates Keep incident status.
3. New external Salesforce Cases may create new incidents in Keep.
4. Bidirectional sync must be idempotent and loop-safe.


## 2. Confirmed Decisions

- Auth mode for Salesforce integration: static `client_id + client_secret` (no OAuth flow).
- Required Salesforce Case custom field: `Keep_Incident_Id__c`.
- Keep statuses in scope: `firing`, `acknowledged`, `resolved`.
- External Salesforce Cases are allowed to create new incidents in Keep.
- Final architecture: `provider + workflow`.


## 3. High-Level Architecture

Channel A (Keep -> Salesforce):

- Trigger source: Keep incident workflow (`created`, `updated`).
- Action: Salesforce provider `_notify` (upsert/update Case).
- Idempotency key: `Keep_Incident_Id__c = Keep incident UUID`.

Channel B (Salesforce -> Keep):

- Trigger source: Salesforce Flow/Apex outbound webhook on Case changes.
- Endpoint in Keep: `POST /incidents/event/salesforce?provider_id=<provider_id>`.
- Action in Keep: provider `_format_incident` converts webhook event to `IncidentDto`.

Channel C (Fallback pull):

- Keep provider `_get_incidents` polls Salesforce Cases with `Keep_Incident_Id__c`.
- Applies status-only updates where status changed.


## 4. Salesforce Configuration Requirements

## 4.1 Integration User

Required capabilities for integration user:

- `API Enabled`.
- Read/Write access to `Case`.
- Read/Write access to custom fields listed below.
- Access to Case statuses used by mapping.
- Permission to create `CaseComment` if comments sync is enabled.

## 4.2 Required Case Fields

Required:

- `Keep_Incident_Id__c`
  - Type: `Text(36)`.
  - Mark as: `External ID`.
  - Constraint: `Unique`.
  - Purpose: deterministic upsert key and reverse mapping.

Recommended:

- `Keep_Incident_Url__c` (URL).
- `Keep_Tenant_Id__c` (Text).

## 4.3 Salesforce Automation

- Outbound webhook must be configured on Case create/update status transitions.
- Webhook payload must include `Case.Id`, `Case.Status`, timestamp, and actor context.
- If feasible, outbound automation should mark events generated by the integration user to reduce echo loops.


## 5. Keep -> Salesforce API Contract

Base URL:

- `<instance_url>/services/data/v61.0`

Auth credentials for API calls:

- `client_id=<client_id>` (static)
- `client_secret=<client_secret>` (static)
- Credentials are sent directly with each request using the integration-specific auth scheme
  (header names or auth format to be confirmed by Salesforce developer).

## 5.1 Upsert Case by External ID (primary path)

HTTP:

- `PATCH /sobjects/Case/Keep_Incident_Id__c/{keep_incident_id}`

Payload (example):

```json
{
  "Subject": "Keep incident: API outage",
  "Description": "Incident details from Keep",
  "Status": "New",
  "Priority": "High",
  "Origin": "Monitoring",
  "Keep_Incident_Url__c": "https://keep.example/incidents/c2509cb3-6168-4347-b83b-a41da9df2d5b",
  "Keep_Tenant_Id__c": "keep"
}
```

Expected behavior:

- If no Case exists with this external id: create Case.
- If Case exists: update Case.

## 5.2 Optional Operations

- Update by Case ID:
  - `PATCH /sobjects/Case/{case_id}`
- Add Case comment:
  - `POST /sobjects/CaseComment`


## 6. Salesforce -> Keep Webhook Contract

Keep endpoint:

- `POST https://api.<keep-domain>/incidents/event/salesforce?provider_id=<provider_id>`

Headers:

- `X-API-KEY: <keep_webhook_api_key>`
- `Content-Type: application/json`

Payload example:

```json
{
  "event_type": "case.updated",
  "occurred_at": "2026-02-18T09:00:00Z",
  "case": {
    "Id": "500XXXXXXXXXXXX",
    "CaseNumber": "00012345",
    "Subject": "API outage",
    "Status": "Closed",
    "Priority": "High",
    "Description": "details",
    "LastModifiedDate": "2026-02-18T08:59:58Z",
    "KeepIncidentId": "c2509cb3-6168-4347-b83b-a41da9df2d5b"
  },
  "actor": {
    "Id": "005XXXXXXXXXXXX",
    "Email": "oncall@company.com",
    "Name": "On Call"
  }
}
```

Minimum required fields in webhook payload:

- `case.Id`
- `case.Status`
- `occurred_at` (or equivalent event timestamp)

Preferred fields:

- `case.KeepIncidentId` (mapped from `Keep_Incident_Id__c`)
- `actor.Email` or `actor.Name`


## 7. Status Mapping Contract

Salesforce -> Keep:

- `New` -> `firing`
- `Working` / `In Progress` / `Escalated` -> `acknowledged`
- `Closed` / `Resolved` -> `resolved`

Keep -> Salesforce:

- `firing` -> `New`
- `acknowledged` -> `Working`
- `resolved` -> `Closed`

Note:

- Exact Salesforce picklist values must be confirmed by Salesforce developer.
- Mapping in provider config should stay overrideable.


## 8. Loop Prevention Contract

Keep side will suppress inbound status updates when:

1. Incoming status already equals current Keep status.
2. Event actor matches recent sync actor metadata.
3. Event timestamp is older than last Keep->Salesforce sync timestamp.

Salesforce side recommendation:

- Include actor and event timestamp in every webhook.
- If possible, tag events originated by integration user.


## 9. Workflow Requirement Clarification

Current platform behavior:

- `Keep -> Salesforce` automatic sync requires workflow action (`provider notify`).
- `Salesforce -> Keep` can work without workflow via incident webhook endpoint.

Therefore, full bidirectional sync requires:

1. Salesforce provider implementation.
2. Keep workflow for outbound create/update/resolve Case actions.


## 10. Acceptance Criteria

1. Creating a Keep incident with status `firing` creates/upserts a Salesforce Case.
2. Keep status `acknowledged` updates Salesforce Case status accordingly.
3. Keep status `resolved` updates Salesforce Case status accordingly.
4. Salesforce status change webhook updates linked Keep incident status.
5. External Salesforce Case without `Keep_Incident_Id__c` creates new Keep incident.
6. Repeated events do not create duplicates.
7. Echo updates do not cause status flip loops.


## 11. Required Feedback From Salesforce Developer

1. Confirm creation of `Keep_Incident_Id__c` as `External ID + Unique`.
2. Confirm exact Case status picklist values for mapping.
3. Confirm integration user permissions are sufficient.
4. Confirm exact request auth format for static credentials (`client_id/client_secret`) and expected header names.
5. Confirm outbound webhook implementation details (Flow/Apex) and final payload shape.
